토스트 표시 예시

버튼이 있으면 본문은 왼쪽, 없으면 가운데 정렬합니다. 아래 예시 다음에 화면별 적용안이 이어집니다.

버튼 있는 안내

실제 문구 “포트폴리오를 저장했어요.”를 두 줄로 표시했습니다. ‘북마크 보기’도 현재 버튼명입니다.

본문은 결과를, 버튼은 다음 행동을 알려 줍니다. 예시의 ‘보기’는 레이블 제안입니다.

버튼 없는 안내

완료 · 결과만 알리기

포트폴리오를 수정했어요.

저장하지 못했어요.입력 내용을 확인해 주세요.

2줄 · 수상 저장 실패

저장하지 못했어요.다시 시도해 주세요.

실제 저장 실패 문구입니다. 본문은 두 줄 모두 가운데 정렬합니다.

바로 실행할 버튼이 없어도, 사용자가 어디서 무엇을 해야 하는지 안내합니다.

진행 중 · 두 유형 공통

작업을 기다리는 동안 스피너을 보여 줍니다. 완료되면 위의 완료 안내로 바뀌고 아이콘은 사라집니다. 실패하면 실패 안내로 바뀝니다. 진행 중에는 버튼이 없습니다.

AS-IS는 현재 문구, TO-BE는 적용할 문구입니다. 같은 안내는 한 행으로 묶었으며, 재시도·파일 선택·입력 확인 안내를 포함합니다.

‘유지’는 문구와 아이콘 기준입니다. 공통 디자인·마침표 규칙은 유지 행에도 적용합니다. AS-IS의 ‘미대조’에는 ‘확인 필요’ 태그를 중복 표시하지 않습니다. 미확인 항목은 ‘확인 필요’ 필터에서 계속 볼 수 있습니다. 수정할 내용과 미확인 내용이 함께 있으면 두 필터에 모두 나타납니다.

기준 화면 402×825, 토스트 x=16·y=642·너비 370·높이 88입니다. 하단 내비게이션 전체 영역은 y=726부터 99pt이며, 실제 탭·추가 버튼은 그 안에서 19.5pt 아래에 있습니다. 따라서 토스트 하단 y=730과 버튼 상단 y=745.5의 간격은 15.5pt입니다.

앱에서는 화면 높이 825나 하단 거리 95를 고정값으로 사용하지 않고, 실제 하단 버튼의 상단을 기준으로 같은 간격을 유지합니다. 내비게이션 높이와 안전 영역이 달라져도 두 번 더하지 않습니다. 키보드·입력창·고정 버튼·시트의 간격은 이 프레임에서 확정하지 않습니다.

현재는 ‘이미 채팅방이 있어요’와 ‘노크는 새로 보내지 않았어요’를 안내하는 버튼 없는 안을 제안합니다. 누가 먼저 노크했는지, 현재 대화할 수 있는지는 단정하지 않습니다. 두 번째 줄의 전송 사실은 서버·iOS 처리 확인 후 적용합니다. 현재 자료만으로는 접근 가능 여부를 판별할 방법이 확인되지 않아 이동 버튼을 보류합니다.

추후 접근 가능한 방을 구분할 방법과 iOS 이동 동작이 확인되면 ‘채팅방 보기’를 추가할 수 있습니다. 나간 방은 재입장 정책을 따릅니다. 방 식별자가 없거나 접근할 수 없는 경우에는 확인된 사유와 가능한 다음 행동에 맞는 별도 안내를 정합니다.

기존 방 검사가 노크 수신 설정 검사보다 앞선다는 설명도 있습니다. 따라서 이 응답을 받았다고 ‘새 노크가 전달됐어요’ 또는 ‘상대가 노크를 받고 있어요’라고 해석하지 않습니다.

버튼 동작 확인: 기존 방으로 이동하는 버튼을 추가할 경우, 해당 방 열기와 필요한 재입장이 가능한지 확인합니다. 기존 API로 이 동작을 지원하는지 먼저 확인하고, 지원하지 않으면 API 수정을 검토합니다. 확인 전에는 버튼을 추가하지 않는 안입니다.
